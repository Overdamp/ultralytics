# 🧠 EX59: โหมดการทำงานหลายภารกิจของ YOLO (YOLO Multi-Task Modes)

ในอดีตนั้น โมเดลตระกูล YOLO ถูกออกแบบมาเพื่อทำหน้าที่ **ตรวจจับวัตถุ (Object Detection)** เป็นหลัก โดยจะระบุตำแหน่งวัตถุด้วยกล่องขอบเขตสี่เหลี่ยมตามแนวแกนปกติ (Horizontal Bounding Boxes) แต่สำหรับโครงสร้าง YOLO ในปัจจุบัน (เช่น YOLOv8 และ YOLOv11) ได้ถูกพัฒนาให้กลายเป็น **เฟรมเวิร์กการทำงานหลายภารกิจ (Multi-Task Framework)** ที่รวมศูนย์เป็นหนึ่งเดียว

ด้วยการแบ่งปันตัวดึงข้อมูลคุณลักษณะร่วมกัน (นั่นคือส่วนโครงสร้างหลัก **Backbone** และส่วนคอ **Neck**) ทำให้โมเดล YOLO สามารถนำส่วนหัวทำนายผลเฉพาะทาง (Prediction **Heads**) แบบต่างๆ มาเชื่อมต่อเพื่อทำงานคอมพิวเตอร์วิทัศน์ที่หลากหลายได้ การออกแบบเช่นนี้ช่วยประหยัดการคำนวณที่ซ้ำซ้อน และมอบอินเทอร์เฟซโปรแกรม (API) ที่เป็นระบบเดียวกันในการแก้ไขโจทย์คอมพิวเตอร์วิทัศน์ที่หลากหลาย

## 1. โหมดภารกิจหลักทั้ง 5 รูปแบบ

แต่ละภารกิจจะใช้ชื่อนามสกุลของโมเดลที่แตกต่างกันออกไป และส่งคืนค่าแอตทริบิวต์เฉพาะภายในอ็อบเจกต์ `Results` ดังนี้:

| ภารกิจ (Task) | นามสกุลโมเดล | แอตทริบิวต์ผลลัพธ์ | คำอธิบายและตัวอย่างการใช้งานจริง |
| :--- | :--- | :--- | :--- |
| **ตรวจจับวัตถุ (Detection)** | `yolo11n.pt` | `results[0].boxes` | ระบุตำแหน่งวัตถุด้วยกรอบสี่เหลี่ยมขนานแกนภาพปกติ *ตัวอย่าง: การนับจำนวนยานพาหนะ, ระบบความปลอดภัยในร้านค้า* |
| **แบ่งส่วนภาพ (Segmentation)** | `yolo11n-seg.pt` | `results[0].masks` | ระบุขอบเขตของวัตถุแต่ละชิ้นลงลึกถึงระดับพิกเซล *ตัวอย่าง: การวัดขนาดเนื้องอกทางการแพทย์, การตรวจจับช่องจราจรของรถยนต์ไร้คนขับ* |
| **จำแนกประเภทภาพ (Classification)** | `yolo11n-cls.pt` | `results[0].probs` | ทำนายประเภทของภาพรวมทั้งหมดโดยระบุเพียงประเภทคลาส โดยไม่มีการระบุตำแหน่งวัตถุ *ตัวอย่าง: การจำแนกประเภททิวทัศน์, การคัดแยกสินค้าในโรงงาน* |
| **ประเมินท่าทาง (Pose/Keypoints)** | `yolo11n-pose.pt` | `results[0].keypoints` | ตรวจหาพิกัดจุดเชื่อมต่อหรือจุดสำคัญทางโครงสร้าง (Keypoints) *ตัวอย่าง: การวิเคราะห์ท่าทางการเคลื่อนไหวทางกีฬา, การยศาสตร์ (Ergonomics)* |
| **กล่องขอบเขตเอียง (OBB - Oriented)** | `yolo11n-obb.pt` | `results[0].obb` | ระบุกล่องขอบเขตวัตถุแบบเอียงตามองศาการหมุน ($x, y, w, h, \theta$) *ตัวอย่าง: ภาพถ่ายดาวเทียมทางอากาศ, การตรวจจับข้อความที่เอียง* |

## 2. ตัวอย่างการเขียนโค้ดด้วย Python (Python Code Demonstration)

ตัวอย่างสคริปต์ต่อไปนี้แสดงวิธีการโหลดโมเดล รันการทำนาย และสกัดผลลัพธ์ของแต่ละโหมดการทำงานใน Python:

```python
from ultralytics import YOLO

# =====================================================================
# 1. การตรวจจับวัตถุมาตรฐาน (Standard Object Detection)
# =====================================================================
model_det = YOLO("yolo11n.pt")
results_det = model_det("demo.jpg")[0]
if results_det.boxes is not None:
    print("--- การตรวจจับวัตถุ (Detection) ---")
    print(f"พิกัดกล่อง (xyxy):\n{results_det.boxes.xyxy[:2]}")  # แสดง 2 กล่องแรก

# =====================================================================
# 2. การแบ่งส่วนวัตถุรายชิ้น (Instance Segmentation)
# =====================================================================
model_seg = YOLO("yolo11n-seg.pt")
results_seg = model_seg("demo.jpg")[0]
if results_seg.masks is not None:
    print("\n--- การแบ่งส่วนภาพ (Segmentation) ---")
    # ดึงพิกัดพิกเซลขอบนอก (Polygons)
    polygons = results_seg.masks.xy
    print(f"ตรวจพบขอบเขตวัตถุทั้งหมด {len(polygons)} ชิ้น")
    print(f"จำนวนจุดของขอบนอกชิ้นแรก: {len(polygons[0])} จุด")

# =====================================================================
# 3. การจำแนกประเภทภาพ (Image Classification)
# =====================================================================
model_cls = YOLO("yolo11n-cls.pt")
results_cls = model_cls("demo.jpg")[0]
if results_cls.probs is not None:
    print("\n--- การจำแนกประเภท (Classification) ---")
    top1_idx = results_cls.probs.top1
    top1_conf = results_cls.probs.top1conf.item()
    print(f"คลาสที่มีคะแนนสูงสุด ID: {top1_idx} (ชื่อคลาส: {results_cls.names[top1_idx]})")
    print(f"ค่าความมั่นใจสูงสุด: {top1_conf:.4f}")

# =====================================================================
# 4. การประเมินท่าทาง (Pose Estimation)
# =====================================================================
model_pose = YOLO("yolo11n-pose.pt")
results_pose = model_pose("demo.jpg")[0]
if results_pose.keypoints is not None:
    print("\n--- การประเมินท่าทาง (Pose Estimation) ---")
    # keypoints.xy มีมิติ: [จำนวนวัตถุ, จำนวนจุดเชื่อมต่อ, พิกัด 2 มิติ]
    # สำหรับมนุษย์ โดยทั่วไปมีจุดสำคัญ 17 จุดตามมาตรฐาน COCO
    keypoints_pixels = results_pose.keypoints.xy.cpu().numpy()
    print(f"พบโครงสร้างท่าทางสำหรับวัตถุจำนวน {len(keypoints_pixels)} ชิ้น")
    print(f"ขนาดมิติข้อมูลโครงสร้างจุดเชื่อมต่อ: {keypoints_pixels.shape}")

# =====================================================================
# 5. การตรวจจับกล่องขอบเขตแบบเอียง (Oriented Bounding Boxes - OBB)
# =====================================================================
model_obb = YOLO("yolo11n-obb.pt")
results_obb = model_obb("demo.jpg")[0]
if results_obb.obb is not None:
    print("\n--- กล่องขอบเขตแบบเอียง (OBB) ---")
    # obb.xyxyxyxy มีมิติ: [จำนวนวัตถุ, 4 มุม, พิกัด 2 มิติ] ของกล่องที่เอียงหมุน
    corners = results_obb.obb.xyxyxyxy.cpu().numpy()
    print(f"พบวัตถุแบบเอียงจำนวน {len(corners)} ชิ้น")
    print(f"พิกัดมุมทั้ง 4 ของวัตถุชิ้นแรก:\n{corners[0]}")
```

## 💡 คำแนะนำจากอาจารย์ (Professor Tips)

### 1. โครงสร้างร่วมและการเรียนรู้แบบถ่ายโอน (Shared Backbones & Transfer Learning)
เนื่องจากภารกิจคอมพิวเตอร์วิทัศน์ที่หลากหลายเหล่านี้ทำงานร่วมกันบน Backbone ดึงข้อมูลชุดเดียวกัน (มักเป็น CSPDarknet หรือใกล้เคียงกัน) คุณจึงสามารถนำค่าน้ำหนักที่เรียนรู้แล้วย้ายข้ามสายงานได้ เช่น หากคุณทำการฝึกสอนโมเดลตรวจจับวัตถุ (Object Detector) บนชุดข้อมูลอุปกรณ์อุตสาหกรรมเฉพาะทางเรียบร้อยแล้ว ฟีเจอร์ที่ Backbone เรียนรู้จะถูกส่งผ่าน (Transfer) ไปใช้ในการแบ่งส่วนภาพ (Segmentation) หรือการตรวจหาท่าทางการหมุนเอียง (Pose) ของวัตถุชนิดเดียวกันได้อย่างรวดเร็ว

### 2. ภาระการประมวลผล (Computational Overhead)
*   **การจำแนกประเภท (`-cls`)** จะทำงานเร็วที่สุดและใช้หน่วยความจำน้อยที่สุด เนื่องจากไม่จำเป็นต้องประมวลผลผ่านส่วนหัวทำนายผลตรวจจับพิกัดกล่องวัตถุอันซับซ้อน
*   **การแบ่งส่วนภาพ (`-seg`)** และ **การตรวจจับวัตถุเอียง (`-obb`)** เป็นงานที่ต้องการพลังการประมวลผลสูงที่สุด เพราะขั้นตอนแบ่งส่วนภาพจำเป็นต้องสร้างแมสค์ต้นแบบ (Mask Prototypes) และคำนวณการประกบค่าแมสค์เข้าด้วยกัน ขณะที่ OBB ต้องรันฟังก์ชันตรีโกณมิติเพื่อคำนวณการหมุนเอียง
*   คุณควรเลือกใช้ภารกิจที่สอดคล้องกับข้อกำหนดจริงของระบบเสมอ อย่าใช้ระบบแบ่งส่วนภาพหากการประเมินตำแหน่งด้วยกรอบสี่เหลี่ยมทั่วไปก็เพียงพอแล้วสำหรับการใช้งานของคุณ!
