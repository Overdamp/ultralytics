# 🧠 EX61: รูปแบบชุดข้อมูล YOLO (YOLO Dataset Format)

การจะฝึกสอนโมเดล Ultralytics YOLO ได้นั้น ข้อมูลของคุณจะต้องถูกจัดระเบียบโครงสร้างไดเรกทอรีในรูปแบบเฉพาะ และมีป้ายกำกับ (annotation) ที่ใช้พิกัดแบบปรับบรรทัดฐาน (normalized coordinates) การทำความเข้าใจรูปแบบข้อมูลนี้มีความสำคัญอย่างยิ่งต่อการเตรียมชุดข้อมูลแบบกำหนดเอง และป้องกันไม่ให้เกิดความผิดพลาดในการจัดตำแหน่งข้อมูลระหว่างการฝึกสอน

---

## 1. โครงสร้างไดเรกทอรี (Directory Structure)

YOLO คาดหวังการแบ่งแยกโฟลเดอร์ภาพออกจากโฟลเดอร์ป้ายกำกับอย่างชัดเจน โดยโครงสร้างมาตรฐานจะแบ่งชุดข้อมูลออกเป็นชุดฝึกสอน (`train`), ชุดตรวจสอบความถูกต้อง (`val`) และชุดทดสอบ (`test`) ซึ่งอาจระบุหรือไม่ก็ได้ ดังนี้:

```text
dataset/
├── data.yaml
├── train/
│   ├── images/
│   │   ├── img001.jpg
│   │   └── img002.jpg
│   └── labels/
│       ├── img001.txt
│       └── img002.txt
├── val/
│   ├── images/
│   │   ├── img003.jpg
│   │   └── img004.jpg
│   └── labels/
│       ├── img003.txt
│       └── img004.txt
└── test/ (optional)
    ├── images/
    └── labels/
```

> [!IMPORTANT]
> ชื่อโฟลเดอร์ `images` และ `labels` จะต้องสะกดให้ถูกต้องตรงเป๊ะ และอยู่ภายใต้โฟลเดอร์ระดับเดียวกัน (เช่น `train/` หรือ `val/`) โดย YOLO จะค้นหาไฟล์ป้ายกำกับที่ตรงกันโดยอัตโนมัติ ด้วยการเปลี่ยนพาร์ทส่วนที่เป็น `/images/` ให้เป็น `/labels/` ในพาธของไฟล์รูปภาพ และสลับนามสกุลไฟล์ (เช่น เปลี่ยนจาก `.jpg` เป็น `.txt`)

## 2. Bounding Box แบบปรับบรรทัดฐาน (Normalized Bounding Box Math)

YOLO จะเก็บป้ายกำกับของรูปภาพแต่ละภาพไว้ในไฟล์ `.txt` ที่มีชื่อเดียวกัน โดยแต่ละบรรทัดในไฟล์จะแทนข้อมูลกล่องขอบเขต (bounding box) ของวัตถุหนึ่งชิ้นด้วยโครงสร้างดังนี้:

```text
<class_id> <x_center> <y_center> <width> <height>
```

*   **`class_id`**: ดัชนีจำนวนเต็มระบุคลาสของวัตถุ เริ่มต้นจากศูนย์ (ตั้งแต่ $0$ ถึง $N-1$ สำหรับชุดข้อมูลที่มี $N$ คลาส)
*   **Coordinates**: พิกัดจุดทศนิยมที่ผ่านการปรับบรรทัดฐาน (normalize) ให้อยู่ในช่วง $[0.0, 1.0]$ ซึ่งทำให้พิกัดเหล่านี้มีคุณสมบัติไม่ขึ้นกับมาตราส่วน (scale-invariant) และเป็นอิสระจากความละเอียดดั้งเดิมของรูปภาพ

### สูตรคำนวณการแปลงพิกัด: จากพิกัดพิกเซลดิบสู่รูปแบบ YOLO (Conversion Math)

สมมติว่าคุณมีพิกัดกล่องขอบเขตระดับพิกเซลดิบในรูปแบบ $[x_{\min}, y_{\min}, x_{\max}, y_{\max}]$ (หรือเรียกว่า Pascal VOC format) และรูปภาพมีความกว้าง $W$ พิกเซล และความสูง $H$ พิกเซล:

1.  **คำนวณความกว้างและความสูงเป็นพิกเซล**:
    $$w_{\text{pixel}} = x_{\max} - x_{\min}$$
    $$h_{\text{pixel}} = y_{\max} - y_{\min}$$

2.  **คำนวณจุดกึ่งกลางเป็นพิกเซล**:
    $$x_{\text{center, pixel}} = x_{\min} + \frac{w_{\text{pixel}}}{2} = \frac{x_{\min} + x_{\max}}{2}$$
    $$y_{\text{center, pixel}} = y_{\min} + \frac{h_{\text{pixel}}}{2} = \frac{y_{\min} + y_{\max}}{2}$$

3.  **หารปรับบรรทัดฐานด้วยขนาดภาพ**:
    $$x_{\text{center}} = \frac{x_{\text{center, pixel}}}{W}$$
    $$y_{\text{center}} = \frac{y_{\text{center, pixel}}}{H}$$
    $$\text{width} = \frac{w_{\text{pixel}}}{W}$$
    $$\text{height} = \frac{h_{\text{pixel}}}{H}$$

## 3. โครงสร้างไฟล์คอนฟิกูเรชัน `data.yaml`

ไฟล์ `data.yaml` ทำหน้าที่เป็นศูนย์กลางการตั้งค่าของชุดข้อมูล ช่วยระบุตำแหน่งที่จัดเก็บไฟล์ภาพ และแมปค่า ID คลาสที่เป็นตัวเลขให้สอดคล้องกับชื่อเรียกของวัตถุที่มนุษย์อ่านเข้าใจ

```yaml
# Path configuration
path: /home/luke/ai_training/datasets/custom_dataset  # Parent directory of the dataset (absolute path recommended)
train: train/images                                   # Relative to path
val: val/images                                       # Relative to path
test: test/images                                     # Optional

# Class configuration
nc: 3                                                 # Number of classes
names:
  0: person
  1: bicycle
  2: car
```

## 💡 คำแนะนำจากอาจารย์ (Professor Tips)

1.  **ขอบเขตพิกัดหลังการปรับบรรทัดฐาน**: พิกัดที่ผ่านการแปลงทั้งหมดจะต้องอยู่ในช่วง $[0.0, 1.0]$ หากคุณมีกล่องขอบเขตที่ยื่นออกนอกรูปภาพเล็กน้อย ให้ใช้ฟังก์ชันอย่าง `np.clip(coord, 0.0, 1.0)` เพื่อบีบพิกัดให้อยู่ในขอบเขตภาพก่อนเขียนลงไฟล์ `.txt`
2.  **ภาพว่างที่ไม่มีวัตถุที่สนใจ (Backgrounds)**: หากบางภาพไม่มีวัตถุที่เราต้องการตรวจจับเลย ห้ามลบภาพนั้นทิ้งเด็ดขาด! ให้เก็บภาพนั้นไว้ในโฟลเดอร์ `images` และสร้างไฟล์ `.txt` ที่เป็น **ไฟล์เปล่า** (ไม่มีข้อความใดๆ) ไว้ในโฟลเดอร์ `labels` ด้วยชื่อเดียวกัน ซึ่งจะช่วยให้โมเดลเรียนรู้เพื่อลดอัตราการทำนายผิดพลาด (false-positives) ได้เป็นอย่างดี
3.  **การระบุพาธไฟล์**: YOLO จะตรวจสอบพาธโดยอิงตามไดเรกทอรีที่คุณสั่งรันคำสั่ง CLI หรือสคริปต์ Python เว้นแต่คุณจะระบุพาธแบบสมบูรณ์ (absolute path) ไว้ในตัวแปร `path:` ของไฟล์ `.yaml` ดังนั้นการใช้พาธสมบูรณ์เสมอถือเป็นแนวทางปฏิบัติที่ดีที่สุดเพื่อหลีกเลี่ยงข้อผิดพลาดเรื่องพาธ
