# 🧠 EX58: การส่งออกโมเดลและการเพิ่มประสิทธิภาพ (YOLO Model Export & Optimization)

การฝึกสอนโมเดลการเรียนรู้เชิงลึก (Deep Learning) มักจะดำเนินการบน PyTorch โดยใช้รูปแบบความแม่นยำทศนิยมแบบ 32 บิต (FP32) เพื่อรักษาความเสถียรในการคำนวณค่าความชัน (Gradients) อย่างไรก็ตาม ไฟล์ค่าน้ำหนักของ PyTorch (`.pt`) ไม่ได้ถูกออกแบบหรือปรับแต่งมาให้เหมาะสมกับการนำไปใช้งานจริงในระบบโปรดักชัน (Production) เนื่องจากไฟล์เหล่านี้จำเป็นต้องทำงานผ่านตัวแปลภาษา Python และระบบรันไทม์ของ PyTorch ซึ่งก่อให้เกิดความล่าช้าและสิ้นเปลืองทรัพยากร (Overhead)

เพื่อให้สามารถนำโมเดลไปปรับใช้กับอุปกรณ์ปลายทาง (Edge devices), เว็บเซิร์ฟเวอร์ หรือระบบฝังตัว (Embedded systems) ได้อย่างมีประสิทธิภาพ คุณจำเป็นต้องแปลงรูปแบบหรือส่งออก (Export) โมเดลไปยังฟอร์แมตเฉพาะทาง (เช่น ONNX, TensorRT, OpenVINO หรือ TFLite) ซึ่งรองรับการทำคอมไพเลอร์ออปติไมเซชัน (Compiler Optimizations), การจำกัดขนาดค่าตัวเลข (Quantization) และการเร่งความเร็วด้วยฮาร์ดแวร์

## 1. แนวคิดหลักของการส่งออกโมเดล (Core Concepts)

ในระหว่างการส่งออกโมเดล YOLO จะทำการแปลงกราฟการคำนวณแบบไดนามิก (Dynamic Computation Graph) ของ PyTorch ให้กลายเป็นรูปแบบลำดับสถิต (Static Serialization Format) ซึ่งฟอร์แมตเป้าหมายในปัจจุบันรองรับการเพิ่มประสิทธิภาพหลักๆ 3 ด้านดังนี้:

### A. การลดทอนความละเอียดของข้อมูล (Half Precision / FP16)
การกำหนดค่า `half=True` จะแปลงค่าน้ำหนักโมเดลจาก FP32 (ทศนิยม 32 บิต) ไปเป็น FP16 (ทศนิยม 16 บิต)
*   **ผลลัพธ์:** ขนาดของไฟล์โมเดลจะลดลงครึ่งหนึ่งทันที (เช่น จาก $12 \text{ MB}$ เหลือเพียง $6 \text{ MB}$)
*   **ประสิทธิภาพ:** สำหรับการ์ดจอ (GPU) ยุคใหม่ที่มีแกนประมวลผล Tensor Cores การประมวลผลด้วย FP16 จะช่วยเพิ่มประสิทธิภาพความเร็ว (Throughput) ได้เกือบสองเท่า โดยแทบจะไม่สูญเสียความแม่นยำในการทำนายเลย

### B. ขนาดภาพอินพุตแบบยืดหยุ่น (Dynamic Input Shapes - `dynamic=True`)
โดยปกติแล้ว โมเดลที่ถูกส่งออกจะมีโครงสร้างขนาดภาพอินพุตที่คงที่ (เช่น กำหนดตายตัวไว้ที่ $1 \times 3 \times 640 \times 640$)
*   **กรณีขนาดคงที่ (Static Shapes):** หากคุณป้อนรูปภาพขนาด $1280 \times 720$ หรือป้อนรูปภาพพร้อมกันเป็นกลุ่ม 4 รูป (Batch of 4) ตัวรันไทม์จะเกิดข้อผิดพลาด (Error) ทันที
*   **กรณีขนาดไดนามิก (Dynamic Shapes):** การตั้งค่า `dynamic=True` ช่วยให้เอ็นจินรันไทม์สามารถรับรูปภาพที่มีขนาดแบทช์และความละเอียดที่เปลี่ยนแปลงได้ในเวลาทำงานจริง โดยระบบจะจัดสรรหน่วยความจำให้สอดคล้องกันโดยอัตโนมัติ

### C. การทำควอนไทเซชันระดับ 8 บิต (INT8 Quantization - `int8=True`)
แปลงค่าค่าน้ำหนัก (Weights) และค่าเป้าหมายการประตุ้น (Activations) จากทศนิยม FP32 ไปเป็นจำนวนเต็มแบบ 8 บิต (INT8)
*   **ผลลัพธ์:** ขนาดไฟล์โมเดลและการใช้งานแบนด์วิดท์ของหน่วยความจำลดลงถึง 4 เท่า
*   **การสอบเทียบ (Calibration):** จำเป็นต้องใช้ตัวอย่างรูปภาพที่เป็นตัวแทนของชุดข้อมูลจริง (Calibration Dataset) เพื่อใช้สร้างตารางจับคู่ค่าระดับความสว่างและสี INT8 เหมาะสมที่สุดสำหรับการใช้งานบนเซิร์ฟเวอร์ที่ประมวลผลด้วย CPU เพียงอย่างเดียว หรืออุปกรณ์ Edge TPU (เช่น Google Coral)

## 2. ตัวอย่างการเขียนโค้ดด้วย Python (Python Code Demonstration)

คุณสามารถส่งออกโมเดลผ่านโค้ด Python ได้ง่ายๆ โดยเรียกใช้เมธอด `model.export()` ดังตัวอย่างด้านล่างนี้:

```python
from ultralytics import YOLO

# 1. โหลดค่าน้ำหนักโมเดลของคุณ (หรือใช้โมเดลที่ฝึกสอนไว้ล่วงหน้า)
model = YOLO("yolo11n.pt")

# 2. ส่งออกเป็น ONNX พร้อมเปิดใช้งาน FP16 และขนาดอินพุตไดนามิก (Dynamic Shapes)
# คำสั่งนี้จะสร้างไฟล์ 'yolo11n.onnx' ขึ้นมาในไดเรกทอรีเดียวกัน
onnx_path = model.export(
    format="onnx",
    half=True,        # ปรับค่าความแม่นยำเป็น FP16
    dynamic=True,     # อนุญาตให้ใช้ขนาดแบทช์และขนาดภาพแบบยืดหยุ่นได้
    opset=12          # กำหนดเวอร์ชัน ONNX opset เพื่อความเข้ากันได้ของระบบ
)
print(f"บันทึกโมเดล ONNX เรียบร้อยแล้วที่: {onnx_path}")

# 3. ส่งออกเป็น TensorRT (สำหรับเร่งความเร็วบนการ์ดจอ NVIDIA GPU)
# TensorRT จะคอมไพล์โมเดลโดยตรงให้เป็นรหัสเครื่องของการ์ดจอตัวนั้น (.engine)
trt_path = model.export(
    format="engine",
    half=True,        # แนะนำให้ใช้ FP16 เพื่อประสิทธิภาพสูงสุดบน Tensor Cores
)
print(f"บันทึกโมเดล TensorRT Engine เรียบร้อยแล้วที่: {trt_path}")

# 4. ส่งออกเป็น INT8 Quantization (ตัวอย่าง TFLite สำหรับอุปกรณ์พกพา/บอร์ดฝังตัว)
# ระบบจะทำการสอบเทียบ (Calibrate) เพื่อลดการสูญเสียความแม่นยำจากการลดขนาดบิต
tflite_path = model.export(
    format="tflite",
    int8=True,        # เปิดใช้งาน INT8 quantization
    data="coco8.yaml" # ระบุเส้นทางไฟล์ตั้งค่า dataset เพื่อใช้สำหรับการสอบเทียบ
)
print(f"บันทึกโมเดล TFLite INT8 เรียบร้อยแล้วที่: {tflite_path}")
```

## 3. การใช้งานผ่าน CLI (CLI Command Equivalence)

คุณสามารถสั่งการส่งออกโมเดลผ่านทางเทอร์มินัลได้โดยตรง:

```bash
# ส่งออกเป็น ONNX พร้อมเปิดใช้ FP16 และ Dynamic Shapes
yolo export model=yolo11n.pt format=onnx half=True dynamic=True

# ส่งออกเป็น TensorRT Engine
yolo export model=yolo11n.pt format=engine half=True

# ส่งออกเป็น TFLite INT8 Quantized model
yolo export model=yolo11n.pt format=tflite int8=True data=coco8.yaml
```

## 💡 คำแนะนำจากอาจารย์ (Professor Tips)

### 1. คำเตือนเกี่ยวกับความเข้ากันได้ของ TensorRT (TensorRT Portability Warning)
ไฟล์โมเดล ONNX สามารถเคลื่อนย้ายไปรันบนเครื่องใดๆ ก็ได้ที่มีรันไทม์รองรับ แต่สำหรับ **ไฟล์ TensorRT engine (`.engine`) จะขึ้นตรงกับฮาร์ดแวร์ที่ใช้สร้างเท่านั้น**
> [!WARNING]
> โมเดล TensorRT ที่คอมไพล์บนการ์ดจอ NVIDIA RTX 4090 จะ **ไม่สามารถ** โหลดหรือทำงานบน RTX 3080 หรือบอร์ด Jetson Orin Nano ได้ แม้ว่าจะรันโค้ดเดียวกันก็ตาม คุณจำเป็นต้องคอมไพล์ไฟล์ `.engine` บน **อุปกรณ์เครื่องเดียวกันกับที่จะใช้รันงานตรวจจับจริง** เสมอ

### 2. เมื่อไหร่ควรใช้ FP16 หรือ INT8?
*   **ใช้ FP16 (`half=True`)** เมื่อต้องการปรับใช้งานบนระบบที่มี GPU ความเร็วสูงเป็นหลัก ใช้งานง่าย ไม่ต้องสอบเทียบค่าข้อมูลเพิ่ม และค่าความแม่นยำ (mAP) ไม่ตกลงเลย
*   **ใช้ INT8 (`int8=True`)** เมื่อต้องการปรับใช้งานบนอุปกรณ์ระดับปลายทาง (Edge Devices เช่น CPU ธรรมดา, Raspberry Pi, Google Coral หรือชิปมือถือ) โปรดจำไว้ว่า INT8 ต้องใช้ภาพสอบเทียบ (ประมาณ 100-500 ภาพ) เพื่อคำนวณตัวคูณการลดสเกล หากข้ามการสอบเทียบนี้ไป อาจส่งผลให้ความแม่นยำของโมเดลดิ่งลงอย่างรุนแรง
