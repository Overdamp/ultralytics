# 🧠 EX51: อินเตอร์เฟซบรรทัดคำสั่ง YOLO (YOLO Command Line Interface - CLI)

อินเตอร์เฟซบรรทัดคำสั่ง (Command Line Interface - CLI) เป็นหนึ่งในวิธีที่ทรงประสิทธิภาพและสะดวกที่สุดในการใช้งาน Ultralytics YOLO ช่วยให้คุณสามารถฝึกสอน (train), ตรวจสอบความถูกต้อง (validate), ทำนายผล (predict), ส่งออกโมเดล (export), ติดตามวัตถุ (track), และทดสอบประสิทธิภาพ (benchmark) ได้โดยตรงจากเทอร์มินัลโดยไม่ต้องเขียนโค้ด Python แม้แต่บรรทัดเดียว

---

## 1. โครงสร้างไวยากรณ์ของ CLI (CLI Syntax Structure)

Ultralytics YOLO CLI ใช้โครงสร้างไวยากรณ์ที่ง่ายและตรงไปตรงมาดังนี้:

```bash
yolo TASK MODE ARGS
```

โครงสร้างนี้ประกอบด้วย 3 ส่วนหลัก:
1. **`yolo`**: คำสั่งเริ่มต้นในการเรียกใช้งาน (entrypoint)
2. **`TASK`**: ระบุงานคอมพิวเตอร์วิทัศน์ที่ต้องการทำ (ระบุหรือไม่ก็ได้ เนื่องจาก YOLO สามารถอนุมานได้จากชื่อโมเดล)
3. **`MODE`**: ระบุขั้นตอนการดำเนินงานที่ต้องการ (จำเป็นต้องระบุ)
4. **`ARGS`**: อาร์กิวเมนต์ที่กำหนดเองในรูปแบบคู่ `key=value` เพื่อเขียนทับค่าคอนฟิกเริ่มต้น

---

## 2. รายละเอียดส่วนประกอบหลัก (Core Components Breakdown)

### A. ประเภทงานคอมพิวเตอร์วิทัศน์ (`TASK`)
YOLO รองรับงานหลัก 5 ประเภท ซึ่งแต่ละประเภทจะมีโครงสร้างสถาปัตยกรรมโมเดลและรูปแบบผลลัพธ์ที่แตกต่างกัน:
*   **`detect`**: การตรวจจับวัตถุ (Object Detection) ระบุตำแหน่งวัตถุด้วยกล่องขอบเขตแนวนอน (bounding box) เช่น `yolo26n.pt`
*   **`segment`**: การแบ่งส่วนวัตถุระดับอินสแตนซ์ (Instance Segmentation) ตรวจจับวัตถุพร้อมระบุขอบเขตระดับพิกเซลที่แม่นยำด้วยหน้ากากภาพ (mask) เช่น `yolo26n-seg.pt`
*   **`classify`**: การจำแนกประเภทภาพ (Image Classification) จำแนกรูปภาพทั้งภาพออกเป็นหมวดหมู่เดียว เช่น `yolo26n-cls.pt`
*   **`pose`**: การประมาณท่าทาง (Pose Estimation) ตรวจจับจุดสำคัญ (keypoints หรือจุดพิกัดข้อต่อ) บนวัตถุที่ตรวจจับได้ โดยทั่วไปมักใช้กับมนุษย์ เช่น `yolo26n-pose.pt`
*   **`obb`**: การตรวจจับวัตถุแบบเอียง (Oriented Object Detection) ตรวจจับวัตถุด้วยกล่องขอบเขตแบบหมุนได้ (rotated bounding box) ซึ่งจำเป็นอย่างยิ่งสำหรับภาพถ่ายทางอากาศ ภาพถ่ายดาวเทียม หรือภาพวัตถุอุตสาหกรรมในมุมเอียง เช่น `yolo26n-obb.pt`

### B. ประเภทโหมดการดำเนินงาน (`MODE`)
โหมดที่ระบุว่าคุณต้องการดำเนินการอย่างไรกับโมเดล:
*   **`train`**: ฝึกสอนโมเดลบนชุดข้อมูลที่ต้องการ (ปรับค่าน้ำหนักตามข้อมูลชุดฝึกสอน)
*   **`val`**: ประเมินความแม่นยำและประสิทธิภาพของโมเดลบนชุดข้อมูลสำหรับตรวจสอบความถูกต้อง (validation dataset)
*   **`predict`**: รันโมเดลทำนายผลบนรูปภาพหรือวิดีโอใหม่ๆ
*   **`export`**: แปลงไฟล์โมเดล PyTorch (`.pt`) ไปเป็นรูปแบบที่เหมาะสมต่อการนำไปใช้งานจริง (เช่น ONNX, OpenVINO, หรือ TensorRT) เพื่อการรันโมเดลที่รวดเร็วยิ่งขึ้น
*   **`track`**: ติดตามวัตถุที่ตรวจจับได้แบบเรียลไทม์ในแต่ละเฟรมของวิดีโอพร้อมมอบ ID ติดตามเฉพาะตัว
*   **`benchmark`**: วัดความเร็วในการประมวลผล (inference time) และความแม่นยำของโมเดลในรูปแบบไฟล์ที่ส่งออกบนฮาร์ดแวร์แบบต่างๆ

## 3. ตัวอย่างการใช้งานคำสั่ง CLI

ตัวอย่างการผสมผสานคำสั่ง `TASK` และ `MODE` บนบรรทัดคำสั่งที่ใช้บ่อย:

### การฝึกสอนโมเดลตรวจจับวัตถุทั่วไป (Object Detection Training)
```bash
yolo detect train model=yolo26n.pt data=coco8.yaml epochs=5 imgsz=640 device=0
```

### การทำนายผลสำหรับโหมดการแบ่งส่วนอินสแตนซ์ (Instance Segmentation Inference)
```bash
yolo segment predict model=yolo26n-seg.pt source='path/to/video.mp4' save=True
```

### การส่งออกโมเดลไปยังรูปแบบ ONNX (Model Export)
```bash
yolo export model=yolo26n.pt format=onnx imgsz=640 half=True
```

### การทดสอบและเปรียบเทียบประสิทธิภาพโมเดล (Benchmarking)
```bash
yolo benchmark model=yolo26n.pt format=onnx,engine imgsz=640 device=0
```

## 3. รายละเอียดพารามิเตอร์และไฮเปอร์พารามิเตอร์ทั่วไป (CLI Options & Hyperparameters Reference)

ตารางด้านล่างแสดงอาร์กิวเมนต์ที่ใช้งานบ่อยที่สุดในคำสั่ง YOLO:

| พารามิเตอร์ (Parameter) | ประเภทข้อมูล (Type) | ค่าเริ่มต้น (Default) | ตัวเลือก / รูปแบบ (Choices) | คำอธิบายรายละเอียดทางเทคนิค (Deep Technical Description) |
| :--- | :--- | :--- | :--- | :--- |
| `model` | `str` | `None` | พาธไปยังไฟล์ `.pt` หรือ `.yaml` | พาธไปยังไฟล์ค่าน้ำหนักโมเดลหรือโครงสร้างสถาปัตยกรรม (เช่น `model=yolo26n.pt` หรือ `model=yolo26n.yaml`) |
| `data` | `str` | `None` | พาธไปยังไฟล์ `.yaml` | พาธไปยังไฟล์คอนฟิกูเรชันชุดข้อมูล ซึ่งระบุรายชื่อคลาส เส้นทางโฟลเดอร์สำหรับ train/val/test |
| `epochs` | `int` | `100` | $[1, \infty)$ | จำนวนรอบการฝึกสอนผ่านชุดข้อมูลทั้งหมดแบบสมบูรณ์ |
| `batch` | `int` | `16` | $[-1, \infty)$ | จำนวนรูปภาพต่อหนึ่งแบทช์การประมวลผล หากตั้งค่าเป็น `-1` จะเป็นการหาขนาดแบทช์สูงสุดที่ GPU รองรับโดยอัตโนมัติ |
| `imgsz` | `int/tuple` | `640` | เลขพหุคูณของ 32 | ขนาดความละเอียดรูปภาพอินพุตเป้าหมาย (เช่น `imgsz=640` หรือระบุเฉพาะเจาะจง `imgsz=480,640`) |
| `device` | `str/int` | `None` | `cpu`, `0`, `0,1`, `cuda` | ฮาร์ดแวร์เป้าหมายที่ใช้ประมวลผล หากใส่ตัวเลขจะหมายถึงหมายเลข GPU (การใส่ค่าเป็นอาเรย์จะรันแบบ DDP หลาย GPU) |
| `save` | `bool` | `True` | `True`, `False` | สั่งบันทึกภาพผลลัพธ์การทำนายพร้อมการวาดตรวจจับวัตถุลงบนหน่วยความจำ |
| `show` | `bool` | `False` | `True`, `False` | แสดงผลลัพธ์ผ่านหน้าต่าง GUI โต้ตอบ (ห้ามรันเป็น True บน Server ที่ไม่มีหน้าจอ GUI) |
| `half` | `bool` | `False` | `True`, `False` | เปิดการทำงานประมวลผลแบบทศนิยมครึ่งความละเอียด (FP16) ช่วยลดหน่วยความจำและเพิ่มความเร็วของโมเดล |

## 4. เปรียบเทียบรหัสโค้ด: Python API vs. CLI (Comparative Code Blocks)

ทุกขั้นตอนการทำงานของ YOLO CLI สามารถเปลี่ยนมาเขียนในรูปแบบโค้ด Python เพื่อประสิทธิภาพที่สูงขึ้นได้ดังนี้:

### การฝึกสอนโมเดลตรวจจับวัตถุ (Object Detection Training)
*   **คำสั่ง CLI**:
    ```bash
    yolo detect train model=yolo26n.pt data=coco8.yaml epochs=5 imgsz=640 device=0
    ```
*   **รหัสโค้ด Python API**:
    ```python
    from ultralytics import YOLO
    
    model = YOLO("yolo26n.pt")
    model.train(data="coco8.yaml", epochs=5, imgsz=640, device=0)
    ```

### การทำนายการแบ่งส่วนอินสแตนซ์ (Instance Segmentation Prediction)
*   **คำสั่ง CLI**:
    ```bash
    yolo segment predict model=yolo26n-seg.pt source="bus.jpg" save=True
    ```
*   **รหัสโค้ด Python API**:
    ```python
    from ultralytics import YOLO
    
    model = YOLO("yolo26n-seg.pt")
    results = model.predict(source="bus.jpg", save=True)
    ```

### การส่งออกโมเดลไปยังฟอร์แมต ONNX (Model Export)
*   **คำสั่ง CLI**:
    ```bash
    yolo export model=yolo26n.pt format=onnx imgsz=640 half=True
    ```
*   **รหัสโค้ด Python API**:
    ```python
    from ultralytics import YOLO
    
    model = YOLO("yolo26n.pt")
    model.export(format="onnx", imgsz=640, half=True)
    ```

## 👨‍🏫 เบื้องลึกสถาปัตยกรรม: CLI vs. Python API (Architectural Deep-Dive)

ในฐานะวิศวกรคอมพิวเตอร์วิทัศน์ คุณต้องตระหนักถึงสิ่งที่เป็นไปในระดับระบบปฏิบัติการ (OS Level) เมื่อรันสองรูปแบบนี้:

### 1. วงจรชีวิตของกระบวนการและความล่าช้าในการเริ่มต้น (Process Life Cycle & Cold-Start)
*   **การรันผ่าน CLI (`yolo ...`)**: ทุกครั้งที่คุณกดรันคำสั่ง ระบบปฏิบัติการจะสร้างโปรเซสใหม่ (Standalone OS Process) โดยโปรเซสนี้ต้องทำการเริ่มต้นตัวตีความ Python (Interpreter) ใหม่ทั้งหมด โหลดไลบรารีขนาดใหญ่อย่าง PyTorch, OpenCV, NumPy และเตรียมไดรเวอร์ CUDA ใหม่ตั้งแต่ต้น ส่งผลให้เกิดความล่าช้าในการเริ่มต้นแบบหน่วงเวลาเย็น (Cold-Start Overhead) สูงถึง **$1.5$ ถึง $3.0$ วินาที** ก่อนจะเริ่มประมวลผลรูปภาพแรก
*   **การเขียนนำเข้าด้วย Python API**: การโหลดไลบรารีและการเตรียมระบบประมวลผล CUDA จะทำเพียงครั้งเดียวตอนเริ่มรันสคริปต์และการเตรียมออบเจกต์ `YOLO` เท่านั้น เมื่อนำโมเดลไปใช้งานในลูปประมวลผลเฟรมต่อเฟรม (Inference loops) เมธอดของโมเดลจะประมวลผลด้วยความเร็วในระดับ **มิลลิวินาที (Sub-millisecond overhead)** โดยไม่มีกระบวนการหน่วงเวลานี้มารบกวนอีกเลย

### 2. การเก็บรักษาหน่วยความจำบน GPU (VRAM & Memory Retention)
*   **การรันผ่าน CLI**: เมื่อคำสั่งทำงานเสร็จสิ้นลง ระบบปฏิบัติการจะทำการยึดคืนพื้นที่ RAM ของระบบและ VRAM ของ GPU กลับคืนโดยทันที
*   **การเขียนนำเข้าด้วย Python API**: ตัวแปรค่าน้ำหนักโมเดล (weights), เมทริกซ์การคำนวณชัน (gradients) และเทนเซอร์ผลลัพธ์จะคงค้างอยู่ในการจัดสรรหน่วยความจำ (Memory pool) ของ CUDA ภายใต้ Python โปรเซสเดิม จนกว่าจะเกิดกระบวนการเก็บกวาดขยะ (Garbage Collection - `del model; torch.cuda.empty_cache()`) หรือสิ้นสุดการทำงานของโปรเซสหลัก

## 💡 คำแนะนำจากอาจารย์ (Professor Tips)

1. **การอนุมานประเภทงานอัตโนมัติ (Auto-Inference of Task)**: ในกรณีส่วนใหญ่ คุณไม่จำเป็นต้องระบุ `TASK` อย่างชัดเจน YOLO มีความฉลาดพอที่จะเดาประเภทงานจากชื่อของโมเดลได้ทันที ตัวอย่างเช่น หากคุณรันคำสั่ง:
   ```bash
   yolo train model=yolo26n-seg.pt data=custom.yaml
   ```
   YOLO จะตรวจพบนามสกุลต่อท้าย `-seg` และรันกระบวนการ `segment` ให้เองโดยอัตโนมัติ
2. **การดาวน์โหลดค่าน้ำหนักอัตโนมัติ (Auto-Download of Weights)**: หากคุณระบุไฟล์โมเดลสำเร็จรูป เช่น `model=yolo26n.pt` และไฟล์ดังกล่าวไม่มีอยู่ในไดเรกทอรีปัจจุบันของเครื่อง CLI จะทำการดาวน์โหลดค่าน้ำหนักจากคลังของ Ultralytics ให้ทันที
3. **การหลีกเลี่ยงข้อผิดพลาด OOM บนเซิร์ฟเวอร์แบบไม่มีหน้าจอ (Headless Server)**: เมื่อรันงานทำนายบนคลาวด์หรือเซิร์ฟเวอร์ระยะไกล ห้ามกำหนดค่า `show=True` เด็ดขาด เพราะ OpenCV GUI จะทำงานล้มเหลวและทำให้โปรแกรมหยุดชะงัก (Crash) ให้ใช้ `show=False` และบันทึกรูปผลลัพธ์ผ่าน `save=True` แทน
