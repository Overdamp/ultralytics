# 🧠 EX52: คอนฟิกูเรชันของโมเดล: YAML vs ค่าน้ำหนักพรีเทรน (Model Configurations: YAML vs Pre-trained Weights)

ใน Ultralytics YOLO โมเดลสามารถถูกโหลดเข้ามาทำงานในสถานะที่แตกต่างกันออกไปขึ้นอยู่กับประเภทของไฟล์ที่ระบุในขั้นตอนการสร้างอ็อบเจกต์ (instantiation) การทำความเข้าใจความแตกต่างระหว่างการโหลดไฟล์คอนฟิกูเรชัน YAML (`.yaml`) และการโหลดไฟล์ค่าน้ำหนัก PyTorch (`.pt`) ถือเป็นพื้นฐานสำคัญในการออกแบบกระบวนการฝึกสอนโมเดล

---

## 1. รากฐานทางคณิตศาสตร์ของการกำหนดค่าน้ำหนักเริ่มต้น (Mathematical Foundations of Weight Initialization)

เมื่อคุณโหลดโมเดลเข้าสู่ระบบปฏิบัติการเพื่อใช้รันการฝึกฝน การเลือกนามสกุลไฟล์จะกำหนดวิธีการตั้งค่าน้ำหนักตัวแปรน้ำหนักเชื่อมโยง ($\mathbf{W}$) และอคติ ($\mathbf{b}$) ของเครือข่ายประสาทเทียม:

### A. การโหลดผ่านไฟล์สถาปัตยกรรม YAML: `YOLO('yolo26n.yaml')`
การเริ่มต้นด้วยคำสั่งนี้จะเป็นการสร้างโมเดลโครงข่ายเปล่าขึ้นมา ค่าน้ำหนักทั้งหมดจะถูกคำนวณแบบสุ่มผ่านอัลกอริทึม **Kaiming (He) Initialization** (ซึ่งคิดค้นมาเพื่อใช้งานกับฟังก์ชันกระตุ้นแบบ ReLU/SiLU ที่ YOLO ใช้งานอยู่เพื่อป้องกันปัญหาความชันหายหรือระเบิด - Exploding/Vanishing Gradients):

สำหรับเลเยอร์ที่มีจำนวนการเชื่อมโยงอินพุตขาเข้า $n_{in}$ (fan-in) ค่าน้ำหนักจะถูกสุ่มตัวอย่างมาจากแจกแจงแบบปกติ (Normal Distribution) ที่มีค่าเฉลี่ยเป็นศูนย์และมีค่าความแปรปรวนที่กำหนดเป็นอัตราส่วน:

$$W \sim \mathcal{N}\left(0, \sigma^2\right) \quad \text{โดยที่} \quad \sigma = \sqrt{\frac{2}{n_{in}}}$$

*   **ลักษณะสำคัญ:**
    *   **มีแต่โครงสร้างสถาปัตยกรรม (Structure Only):** โหลดโครงสร้างเลเยอร์ (Backbone, Neck, Head) จากไฟล์ YAML แต่ค่าน้ำหนักเป็นแบบสุ่มดิบ
    *   **ไม่มีความรู้ดั้งเดิม (Zero Prior Knowledge):** โมเดลไม่รู้จักเส้น เส้นขอบ หรือรูปร่างใดๆ เลย ต้องฝึกสอนใหม่หมดจากศูนย์
    *   **ต้องการชุดข้อมูลขนาดใหญ่มาก:** เพื่อให้โมเดลลู่เข้าสู่จุดที่ประเมินผลได้แม่นยำ จำเป็นต้องใช้ข้อมูลภาพเป็นจำนวนหมื่นหรือแสนภาพขึ้นไป

### B. การโหลดผ่านค่าน้ำหนักที่พรีเทรนแล้ว: `YOLO('yolo26n.pt')`
การโหลดจากไฟล์จุดตรวจสอบจุดตรวจ `.pt` จะเป็นการดึงโครงสร้างพร้อมค่าน้ำหนักที่เคยผ่านการฝึกอบรมบนชุดข้อมูลขนาดใหญ่อย่าง COCO (80 คลาส) มาเรียบร้อยแล้ว:

*   **ลักษณะสำคัญ:**
    *   **การเรียนรู้ถ่ายโอน (Transfer Learning):** นำความสามารถในเลเยอร์การสกัดคุณลักษณะ (Backbone และ Neck) ซึ่งมีความสามารถในการจำแนกรูปทรง เส้นขอบ แสงเงา และลวดลายทั่วไปอยู่แล้วมาใช้งานต่อโดยตรง
    *   **การตัดส่วนหัวและเริ่มต้นใหม่ (Head Stripping):** หากชุดข้อมูลเป้าหมายของคุณมีจำนวนคลาส $C$ (ซึ่งไม่เท่ากับ 80 คลาสของ COCO) YOLO จะทำการแกะและตัดเลเยอร์ส่วนทำนายผลคลาสสุดท้ายออก และสุ่มน้ำหนักเฉพาะหัวทำนายชุดใหม่ขึ้นมาแทนที่:
        $$\mathbf{W}_{head} \in \mathbb{R}^{80 \times D} \quad \xrightarrow{\text{ตัดและสุ่มเริ่มต้นใหม่}} \quad \mathbf{W}_{head\_new} \in \mathbb{R}^{C \times D}$$
        ในขณะที่ส่วนสกัดคุณลักษณะอื่น ๆ จะยังคงค่าน้ำหนักเดิมไว้ ทำให้ลู่เข้าสู่จุดเหมาะสม (Convergence) ได้ไวขึ้นและใช้ข้อมูลในการฝึกฝนน้อยลงอย่างมาก

## 2. การเริ่มต้นใช้งานโมเดลด้วย Python API

รายละเอียดการโหลดรูปแบบต่างๆ ในโค้ด Python สำหรับใช้งานจริง:

```python
from ultralytics import YOLO

# แบบที่ 1: สร้างโมเดลเปล่า ค่าน้ำหนักเริ่มสุ่มใหม่หมดจากศูนย์ (Random Kaiming weights)
model_scratch = YOLO("yolo26n.yaml")

# แบบที่ 2: โหลดโมเดลที่พรีเทรนบน COCO มาล่วงหน้าแล้วเพื่อทำ Transfer Learning (แนะนำสำหรับงานทั่วไป)
model_pretrained = YOLO("yolo26n.pt")

# แบบที่ 3: แบบผสม (Hybrid) - สร้างโครงสร้างปรับแต่งจาก YAML แล้วโหลดค่าน้ำหนักที่ใกล้เคียงจากไฟล์ .pt เข้าไป
model_hybrid = YOLO("custom_yolo26n.yaml")
model_hybrid.load("yolo26n.pt")  # จะโหลดเฉพาะเลเยอร์ที่มีชื่อและขนาดโครงสร้างตรงกัน
```

## 3. การอ้างอิงพารามิเตอร์ของ API สำหรับการโหลดโมเดล (API Parameter Reference for Model Loading)

ตัวสร้างคลาส `YOLO()` และอ็อบเจกต์โมเดลที่โหลดมา รองรับคอนฟิกูเรชันต่างๆ ดังนี้:

| พารามิเตอร์ (Parameter) | ประเภทข้อมูล (Type) | ค่าเริ่มต้น (Default) | ตัวเลือก / รูปแบบ (Choices) | คำอธิบายรายละเอียดทางเทคนิค (Deep Technical Explanation) |
| :--- | :--- | :--- | :--- | :--- |
| `model` | `str` | *จำเป็น* | `.pt`, `.yaml` หรือชื่อโมเดล | เส้นทางพาธไปยังน้ำหนักโมเดลหรือสถาปัตยกรรม (เช่น `'yolov8n.pt'`, `'yolo11s.yaml'`) |
| `task` | `str` | `None` | `'detect'`, `'segment'`, `'classify'`, `'pose'`, `'obb'` | บังคับระบุหรืองดระบุประเภทงานของโมเดล |
| `verbose` | `bool` | `True` | `True`, `False` | เปิด/ปิดการแสดงพิมพ์โครงสร้างเลเยอร์สถาปัตยกรรมโดยละเอียดขณะเริ่มโหลดโมเดล |

## 4. เปรียบเทียบรหัสโค้ด: Python API vs. CLI (Comparative Code Blocks)

### การโหลดและสร้างสถาปัตยกรรมโมเดลรูปแบบต่างๆ

*   **รหัสโค้ด Python API**:
    ```python
    from ultralytics import YOLO
    
    # วิธีที่ 1: ฝึกฝนจากศูนย์ใหม่หมด (ค่าน้ำหนักสุ่ม Kaiming Normal)
    model_scratch = YOLO("yolo26n.yaml")
    
    # วิธีที่ 2: การเรียนรู้ถ่ายโอนจากจุดตรวจสอบ COCO พรีเทรน
    model_pretrained = YOLO("yolo26n.pt")
    
    # วิธีที่ 3: แบบผสม (โหลดสถาปัตยกรรมกำหนดเอง + ถ่ายโอนค่าน้ำหนักที่เข้ากันได้)
    model_hybrid = YOLO("custom_yolo26n.yaml")
    model_hybrid.load("yolo26n.pt")
    ```
*   **คำสั่ง CLI**:
    ```bash
    # วิธีที่ 1: ฝึกฝนจากศูนย์ใหม่หมด
    yolo train model=yolo26n.yaml data=coco8.yaml epochs=5
    
    # วิธีที่ 2: การเรียนรู้ถ่ายโอน
    yolo train model=yolo26n.pt data=coco8.yaml epochs=5
    
    # วิธีที่ 3: แบบผสม (ระบุไฟล์สถาปัตยกรรม และแนบพรีเทรน)
    yolo train model=custom_yolo26n.yaml pretrained=yolo26n.pt data=coco8.yaml epochs=5
    ```

## 💡 คำแนะนำจากอาจารย์ (Professor Tips)

### 1. การแช่แข็งเลเยอร์ Backbone สำหรับการปรับจูนอย่างละเอียด (Freezing Backbone Layers)
เมื่อคุณทำการปรับจูนอย่างละเอียดบนชุดข้อมูลที่มีขนาดเล็กมาก (เช่น ต่ำกว่า 500 ภาพ) การฝึกสอนและอัปเดตน้ำหนักทุกเลเยอร์ของโมเดลจะนำไปสู่ปัญหาการลืมความรู้ทั่วไปและ Overfitting คุณสามารถแก้ไขได้โดยการแช่แข็ง (Freeze) ค่าน้ำหนักเลเยอร์ในส่วนสกัดคุณลักษณะ (Backbone) เพื่อสั่งให้อัปเดตเฉพาะน้ำหนักของเลเยอร์ส่วนทำนายเท่านั้น:
```python
from ultralytics import YOLO

# โหลดค่าน้ำหนักพรีเทรน
model = YOLO("yolo26n.pt")

# แช่แข็งโครงสร้างส่วนสกัดคุณลักษณะ 10 เลเยอร์แรก (ส่วน Backbone)
results = model.train(data="custom.yaml", epochs=30, freeze=10)
```

### 2. ข้อแลกเปลี่ยนของการปรับสเกลขนาดโมเดล (Model Scaling Trade-offs)
YOLO ใช้ตัวคูณความลึกและความกว้าง (depth/width factors) ในไฟล์ YAML คอนฟิกเพื่อขยายขนาดสถาปัตยกรรม:
*   **รุ่น Nano (n) / Small (s)**: เหมาะสมที่สุดสำหรับเครื่องประมวลผล CPU และอุปกรณ์ Edge มีอัตราการประมวลผลต่อวินาที (FPS) ที่สูงมาก แต่อาจขาดความแม่นยำในการระบุกล่องขอบเขตสำหรับวัตถุขนาดเล็กหรือทับซ้อน
*   **รุ่น Medium (m) / Large (l) / Extra-Large (x)**: เหมาะสำหรับเครื่องที่มี GPU ความเร็วสูง ให้ค่าพิกัดตรวจจับที่แม่นยำและเสถียร แต่ประมวลผลช้ากว่าและกินหน่วยความจำ VRAM ของ GPU มากกว่า
