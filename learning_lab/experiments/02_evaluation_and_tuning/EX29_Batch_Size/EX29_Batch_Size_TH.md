# 🧠 EX29: การวิเคราะห์ขนาดกลุ่มข้อมูล (Batch Size Analysis)

ขนาดกลุ่มข้อมูล (Batch size) คือไฮเปอร์พารามิเตอร์ในการฝึกสอนโมเดล ที่กำหนดจำนวนตัวอย่างข้อมูลที่จะถูกประมวลผลโดยโครงข่ายประสาทเทียมในการส่งผ่านไปข้างหน้าและย้อนกลับ (Forward/backward pass) หนึ่งครั้ง ก่อนที่จะมีการอัปเดตค่าน้ำหนักภายในของโมเดล

---

## 1. ข้อดีข้อเสียระหว่างขนาดกลุ่มข้อมูลขนาดเล็กและขนาดใหญ่ (Trade-Offs: Small vs. Large Batch Sizes)

การปรับขนาดกลุ่มข้อมูลจะส่งผลต่อความเร็วในการฝึกสอน ความแม่นยำของเกรเดียนต์ และผลของการทำให้เป็นระเบียบ (Regularization):

### A. ขนาดกลุ่มข้อมูลขนาดเล็ก (เช่น 2, 4, 8, 16)
*   **สัญญาณรบกวนของเกรเดียนต์ (Gradient Noise):** เกรเดียนต์จะถูกคำนวณจากรูปภาพจำนวนน้อย ทำให้ค่าที่ได้มีความผันผวนหรือมีสัญญาณรบกวนสูง (Stochastic)
*   **ผลการทำให้เป็นระเบียบ (Regularization Effect):** สัญญาณรบกวนนี้ทำหน้าที่เสมือนตัวช่วยควบคุมความซับซ้อน ป้องกันไม่ให้โมเดลปรับตัวเข้ากับข้อมูลฝึกสอนแนบแน่นเกินไป (Overfitting) และช่วยให้โมเดลหลุดพ้นจากค่าต่ำสุดเฉพาะกลุ่มที่ลึกและชันได้ ซึ่งมักนำไปสู่ความสามารถในการสรุปนัยทั่วไป (Generalization) ที่ดีขึ้น
*   **ประสิทธิภาพของหน่วยความจำ:** ใช้หน่วยความจำ (VRAM) ของ GPU น้อยมาก
*   **ข้อเสีย:** ใช้เวลานานขึ้นในการประมวลผลจนครบหนึ่ง Epoch เนื่องจากมีการอัปเดตน้ำหนักบ่อยครั้งขึ้น

### B. ขนาดกลุ่มข้อมูลขนาดใหญ่ (เช่น 64, 128, 256)
*   **ความเสถียรของเกรเดียนต์:** เกรเดียนต์ที่คำนวณได้มีความแม่นยำสูงและเป็นตัวแทนที่ดีของชุดข้อมูลทั้งหมด
*   **ความเร็ว:** ใช้ประโยชน์จากการประมวลผลแบบขนานของ GPU ได้อย่างสูงสุด ส่งผลให้การฝึกสอนในแต่ละ Epoch เสร็จสิ้นอย่างรวดเร็ว
*   **ข้อเสีย:** ต้องการหน่วยความจำ GPU ขนาดมหาศาล และอาจทำให้โมเดลตกลงไปอยู่ในค่าต่ำสุดเฉพาะกลุ่มแบบแบน (Flat local minima) ซึ่งในบางครั้งอาจส่งผลให้ความแม่นยำในการสรุปนัยทั่วไป (Generalization accuracy) ลดลงเล็กน้อย

---

## 2. กฎการปรับขนาดอัตราการเรียนรู้ (Learning Rate Scaling Rules)

เมื่อคุณเปลี่ยนขนาดกลุ่มข้อมูล คุณจำเป็นต้องปรับอัตราการเรียนรู้ ($\alpha$) ตามไปด้วย แนวทางที่นิยมใช้กันมากที่สุดคือ **กฎการปรับขนาดเชิงเส้น (Linear Scaling Rule)**:
*   หากคุณเพิ่มขนาดกลุ่มข้อมูลขึ้น $k$ เท่า คุณควรเพิ่มอัตราการเรียนรู้เริ่มต้น (`lr0`) ขึ้น $k$ เท่าเช่นกัน

$$\text{Learning Rate}_{\text{new}} = \text{Learning Rate}_{\text{base}} \times \left( \frac{\text{Batch Size}_{\text{new}}}{\text{Batch Size}_{\text{base}}} \right)$$

เหตุผลเป็นเพราะเมื่อใช้กลุ่มข้อมูลขนาดใหญ่ขึ้น จำนวนครั้งในการอัปเดตน้ำหนักต่อหนึ่ง Epoch จะลดลง ดังนั้นการอัปเดตแต่ละครั้งจึงจำเป็นต้องก้าวให้ยาวขึ้นเพื่อเดินทางให้ได้ระยะทางเท่าเดิม

## 🔬 ความเชื่อมโยงกับการมองเห็นของคอมพิวเตอร์: ข้อผิดพลาด CUDA OOM
ในการฝึกสอน YOLO การตั้งค่าขนาดกลุ่มข้อมูลที่ใหญ่เกินกว่าความจุ VRAM ของ GPU จะทำให้เกิดข้อผิดพลาดที่พบบ่อยและน่าปวดหัวคือ **CUDA Out of Memory (OOM)**:

```text
OutOfMemoryError: CUDA out of memory. Tried to allocate ...
```

### วิธีแก้ไขปัญหา OOM:
1.  **ลดขนาดกลุ่มข้อมูล (Batch Size):** ปรับลดค่า `batch=32` ให้เหลือ `batch=16` หรือ `batch=8`
2.  **ลดขนาดรูปภาพ:** ปรับลดความละเอียดของภาพนำเข้าจาก `imgsz=640` เป็น `imgsz=320` (เนื่องจากการใช้หน่วยความจำจะเพิ่มขึ้นเป็นกำลังสองตามความละเอียดของภาพ: $O(W \times H)$)
3.  **สะสมเกรเดียนต์ (Gradient Accumulation):** ตั้งค่าขนาดกลุ่มข้อมูลให้เล็ก แต่กำหนดให้อัปเดตน้ำหนักหลังจากประมวลผลผ่านไปหลายๆ กลุ่มข้อมูลแทน

```python
from ultralytics import YOLO

model = YOLO('yolo26n.pt')

# Training with batch size of 8 to prevent CUDA OOM
model.train(
    data='datasets/coco8/overall-ptt-object-detection.v11i.yolov11/data.yaml',
    epochs=10,
    batch=8,       # Force batch size to 8
    imgsz=640
)
```
