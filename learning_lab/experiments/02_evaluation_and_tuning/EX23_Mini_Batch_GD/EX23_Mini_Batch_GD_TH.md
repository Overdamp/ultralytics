# 🧠 EX23: การไล่ตามความชันแบบแบ่งกลุ่มย่อย (Mini-Batch Gradient Descent)

Mini-Batch Gradient Descent (การไล่ตามความชันแบบแบ่งกลุ่มย่อย) เป็นหนึ่งในตัวแปรของขั้นตอนวิธี Gradient Descent ที่ทำการแบ่งชุดข้อมูลฝึกสอนออกเป็นกลุ่มเล็กๆ ขนาดพอเหมาะที่จัดการได้ง่ายเรียกว่า "กลุ่มย่อย" (Mini-batches) น้ำหนักของโมเดลจะได้รับการอัปเดตหลังจากประเมินแต่ละกลุ่มย่อยเสร็จสิ้น ซึ่งเป็นการผสมผสานข้อดีของทั้ง Batch GD และ Stochastic GD เข้าด้วยกัน

---

## 1. การเปรียบเทียบตัวแปรของ Gradient Descent

| ตัวชี้วัด | Batch Gradient Descent | Stochastic Gradient Descent (SGD) | Mini-Batch Gradient Descent |
| :--- | :--- | :--- | :--- |
| **ขนาดกลุ่ม (Batch Size)** | ชุดข้อมูลทั้งหมด ($m$) | 1 ตัวอย่างพอดี | กลุ่มย่อยขนาดเล็ก ($B$) เช่น 16, 32 |
| **เกรเดียนต์** | มีความแม่นยำสูงและมีความเสถียร | มีสัญญาณรบกวนมากและคดเคี้ยว | มีความเสถียรปานกลางและมีสัญญาณรบกวนเล็กน้อย |
| **ความเร็ว** | ช้ามากเมื่อข้อมูลมีขนาดใหญ่ | ช้า (ไม่สามารถใช้การแปลงเป็นเวกเตอร์ หรือ Vectorization ได้) | รวดเร็ว (ใช้การเร่งการคำนวณเมทริกซ์ด้วย GPU) |
| **หน่วยความจำ** | สูง (มักทำให้เกิด OOM - Out of Memory) | ต่ำมาก | ควบคุมได้ (มีขนาดพอดีกับ VRAM) |
| **การสรุปนัยทั่วไป (Generalization)** | อาจติดหล่มอยู่ที่ค่าต่ำสุดเฉพาะกลุ่ม | สัญญาณรบกวนช่วยให้หลุดพ้นจากค่าต่ำสุดเฉพาะกลุ่มได้ | มีความสมดุลและให้ผลการสรุปนัยทั่วไปที่ดีที่สุด |

---

## 2. สูตรทางคณิตศาสตร์ (Mathematical Formulation)

กำหนดให้ขนาดของกลุ่มย่อย (Mini-batch size) เป็น $B$ (โดยที่ $1 < B < m$)

สำหรับกลุ่มย่อยที่กำหนดซึ่งประกอบด้วยตัวอย่างข้อมูลฝึกสอน $\{ (x^{(1)}, y^{(1)}), \dots, (x^{(B)}, y^{(B)}) \}$ ฟังก์ชันการสูญเสียจะถูกคำนวณเป็นค่าเฉลี่ยความสูญเสียจากชุดข้อมูลย่อยนี้:

$$J_{\text{mini-batch}}(w, b) = \frac{1}{2B} \sum_{i=1}^{B} \left( h_{w,b}(x^{(i)}) - y^{(i)} \right)^2$$

พารามิเตอร์จะถูกอัปเดตโดยใช้เกรเดียนต์ที่คำนวณจากตัวอย่าง $B$ ตัวเหล่านี้เท่านั้น:

$$w \leftarrow w - \alpha \frac{1}{B} \sum_{i=1}^{B} \left( h_{w,b}(x^{(i)}) - y^{(i)} \right) \cdot x^{(i)}$$
$$b \leftarrow b - \alpha \frac{1}{B} \sum_{i=1}^{B} \left( h_{w,b}(x^{(i)}) - y^{(i)} \right)$$

## 💻 การเร่งความเร็วด้วยฮาร์ดแวร์และการแปลงเป็นเวกเตอร์ (Hardware Acceleration & Vectorization)
GPU รุ่นใหม่ๆ (เช่น NVIDIA Tesla, RT-cores) ได้รับการปรับแต่งให้มีความเหมาะสมสำหรับการคูณเมทริกซ์แบบขนาน (Parallel matrix multiplications)
*   หากเราฝึกสอนด้วย **SGD (ขนาด Batch = 1)** GPU จะต้องรอการประมวลผลแบบเรียงลำดับ ซึ่งจะปล่อยให้หน่วยประมวลผล CUDA นับพันคอร์ว่างงาน
*   หากเราใช้ **Mini-Batch GD (ขนาด Batch = 16 หรือ 32)** เราจะนำภาพหลายภาพมาซ้อนรวมกันเป็นเทนเซอร์ 4 มิติ (4D tensor) ที่มีรูปร่าง (Shape) ดังนี้:
    $$\text{Shape} = [\text{Batch}, \text{Channels}, \text{Height}, \text{Width}]$$
    ซึ่งช่วยให้ GPU สามารถคำนวณเกรเดียนต์ของทั้ง 16 ภาพพร้อมๆ กันได้ ส่งผลให้เวลาในการฝึกสอนลดลงอย่างมหาศาล

## 🔬 ความเชื่อมโยงกับการมองเห็นของคอมพิวเตอร์: กลุ่มข้อมูลสำหรับการฝึกสอน YOLO (YOLO Training Batch)
โมเดล YOLO จะใช้ Mini-Batch GD ในระหว่างการฝึกสอน คุณสามารถควบคุมสิ่งนี้ได้ผ่านบรรทัดคำสั่ง (Command line) หรือโค้ด Python โดยใช้อาร์กิวเมนต์ `batch` (ซึ่งมีค่าเริ่มต้นเป็น `16`):

```bash
yolo train model=yolo26n.pt data=data.yaml batch=16 imgsz=640
```
การตั้งค่านี้จะแบ่งรูปภาพในชุดข้อมูล PTT ที่คุณสร้างขึ้นเองออกเป็นกลุ่มย่อยกลุ่มละ 16 รูป ซึ่งจะช่วยเพิ่มประสิทธิภาพสูงสุดให้กับการประมวลผลของ GPU ในขณะเดียวกันก็รักษาการลู่เข้าที่มีเสถียรภาพไว้ได้
